| `RISK-23` | **A KPI measured through the VLM is only reproducible while inference is served serially.** Measured 2026-07-28 on this box (vLLM, `nvidia/cosmos-reason1-7b`, one real camera frame): 15/15 byte-identical responses issued serially — even *without* a seed — but 4 identical requests issued CONCURRENTLY returned 2× `soiled` and 2× `healthy`. Continuous batching changes the arithmetic and no request-level parameter (`temperature`, `seed`, `top_k`) fixes it. The mission FSM is serial today, so any future parallel screening would silently make every KPI non-reproducible. | `FR-02`, `FR-03`, `FR-17`, `NFR-02`, `KPI-01`, `KPI-03` | Decoding is pinned greedy and recorded per run (`cosmos_reason.DEFAULT_SAMPLING` → the run record's `perception.sampling`); `run.py --repeat N` quotes a spread instead of a number and attributes each disagreement to renderer vs. model by frame digest. **Before any batched/parallel inference path is added, re-measure and state the variance it introduces.** | Open — mitigated for serial runs, unresolved for batched ones |
| `RISK-24` | **RTX capture is NOT bit-reproducible — not even from a camera that never moves.** Measured 2026-07-28 (`tools/probe_render_determinism.py`, 640x480, low-sun Khavda stage): 4 captures held still → **4 distinct digests**, 0.85/255 mean pixel difference, ~52% of pixels changed; leave-and-return is worse (2.39 mean, 88% of pixels); 10 extra settling steps do **not** converge it (0.70 mean). A 3-repeat mission run agreed: **40/40 panels rendered differently between repeats.** So the Session-10b verdict flip needs no exotic explanation, and — critically — bit-exact digests cannot attribute a flip, because they *always* differ in a rendered run. | `NFR-02`, `KPI-01`, `KPI-03` | **Resolved as a measured platform property, and designed around.** The amplitude is what matters: block-averaged into an 8x8 thumbnail, the same scene differs by **0.20–0.59 LSB** while a genuinely different picture (shaded panel vs. the unshaded control) differs by **35.5 LSB** — a ~60x gap. `perception.base.frame_thumbnail` + `kpi.variance.thumbnails_differ` (tolerance 1.0) therefore attribute flips on "same *picture*", not "same bits", and both counts are reported. A quantised *hash* was tried first and rejected by measurement: 256 blocks at 16 levels still flipped a boundary on ~3 of 4 unchanged captures. | **Resolved 2026-07-28** — renderer is stochastic at sub-LSB amplitude; attribution uses a measured tolerance, and any repeat set showing a *materially* different picture is flagged as not comparing like with like |

| `RISK-25` | **Verdicts are not stable under sub-perceptual input noise — and this is the mechanism behind the flips, not decoding.** Given identical input *bytes* Reason-1 is byte-repeatable (`RISK-23`). But the renderer never delivers identical bytes (`RISK-24`), and that difference — imperceptible at picture level, ~1.3 LSB on an 8x8 thumbnail — was enough to change a verdict. Measured over two 3-repeat sets on `demo_video` (24 panels, 7 escalations each): `R258-C013` (injected `soiled`) → `soiled/hotspot/hotspot` in set A; `R258-C014` (injected `hotspot`) → `healthy/healthy/soiled` in set B. The model's own notes describe genuinely different readings ("opaque tan or brown patch… soiling" vs. "a small, bright red/orange spot… localized overheating"), so it is confident and wrong, not hedging. Both flips are on **faulted** panels, i.e. this is `KPI-01` fragility; `KPI-03` was 0.000 and stable across all six runs. Note the taxonomy definitions in `_STATE_DEFINITIONS` were added to fix exactly this soiled↔hotspot confusion — they reduced it, they did not remove it. | `FR-02`, `FR-03`, `KPI-01`, `NFR-06` | Not fixable by pinning decoding (already greedy) and arguably **should not** be "fixed" in the twin: a real camera has sensor noise, so a model that flips on it would flip in the field too. Treat it as a genuine perception-robustness requirement — quantify with `--repeat` (per-panel agreement is reported), and drive it down with prompt/model work or ensembling rather than by making the renderer deterministic. `KPI-01` on this stage is 0.875 with **2 of 3 misses stable across repeats**, so the headline is a discrimination problem first and a variance problem second. | Open — measured and quantified; needs a perception-robustness plan, not a sim fix |

## Register hygiene

- When a `RISK-nn` resolves, update its **Status** in place (`Resolved
  YYYY-MM-DD — <what was confirmed>`); do not delete the row — it's the audit
  trail for why a design decision was made the way it was.
- When a new ⚠-verify item surfaces during implementation, add it here with
  the next sequential ID and link it from whichever requirement/hazard/slice
  it blocks — don't let open questions live only in code comments or PR
  descriptions.
- `RISK-02`, `RISK-06`, and `RISK-08` are called out as **gating risks** in
  `07-roadmap-and-milestones.md` because their slice cannot start design work
  in earnest until they're resolved one way or the other — everything else is
  a parallel-track verification.
